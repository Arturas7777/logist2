## 1. TL;DR

Logist2 генерирует пакет документов автовоза. Слот `SIGNATURE` может быть пуст. Задумка: вытянуть рукописный росчерк с главной страницы паспорта РБ и поставить в обязательство / платёжку.

На **чётких сканах** детерминированная очистка в целом работала.

На **смазанных телефонных фото** (типичный кейс — клиент **Пытель Виктория**) человек на снимке **видит** синюю шариковую подпись, а ни один пайплайн не дал картинку, которую владелец продукта принял бы как «ту же подпись». Последние результаты — россыпь синих осколков. Владелец: «Это похоже на подпись?» — нет.

**Решение 09.09.2026:** авто-извлечение **выключено**. Клиенты снова загружают фото подписи вручную. Нормализатор ручной загрузки и размер в PDF **не трогать**.

---

## 2. Зачем это было в продукте

- Слот `SIGNATURE` пуст → хотели не отваливать генерацию, если есть только паспорт.
- Вход: `auto_signature_from_passport` в `core/services/transport_package_actions.py` → `extract_signature_from_passport`.
- PNG в слот (`is_generated=True`), клиент видит превью, может заменить.
- PDF: `core/services/transport_docs_pdf.py` → `_signature_flowable`.

Ручная загрузка **уже работала** и имела приоритет. Авто-путь — запасной.

**Сейчас (после отката):** без загруженной подписи «Сгенерировать всё» даёт ошибку «загрузите фото подписи». Одиночная генерация обязательства по-прежнему может собрать PDF без подписи (предупреждение в notices) — как до фичи.

## 3. Критерий успеха (не выполнен)

Смотреть глазами на эталон и на результат рядом. Не на «долю чернильных пикселей».

1. Та же подпись: тот же старт, те же петли, те же два высоких росчерка вправо. Не «похожая закорючка».
2. Тонкие **сплошные** линии шариковой, не толстые кляксы и не пунктир осколков.
3. Фон прозрачный, штрихи синие (как после `normalize_signature_image`).
4. Нет линейки поля, штампа «32», печатного «Подпись владельца», гильоша.
5. Нельзя нарисовать **новую** подпись. Если восстановить нельзя — `None` и просьба загрузить фото.

Эталон Пытель (то, что видит человек на кропе):

- синяя шариковая на бежевой бумаге, смаз, зерно;
- слева завиток вроде «П», связанные петли, справа **два высоких росчерка вверх**;
- вверху слева фиолетовый штамп «32»;
- **под** росчерком прямая тёмная линейка поля; низ — обрезки «подпис…».

## 5. Как был устроен пайплайн (перед откатом)

```
фото/PDF паспорта
  → рендер страниц 300 dpi (scan_extractor._load_page_images)
  → Claude Vision: JSON-рамка left/top/right/bottom в долях 0..1
  → кроп с запасом (снизу урезан, чтобы меньше линейки)
  → апскейл, если сторона < 360 / рабочая сторона ~800
  → либо Оцу-очистка (чёткие сканы) + normalize_signature_image
  → либо «плохой» путь (менялся от версии к версии, см. §4)
```

Vision: Anthropic Claude, `ANTHROPIC_API_KEY`. Модель **не умеет вернуть растр**, только JSON.

Нормализатор `core/services/signature_normalizer.py` заточен под **чёткое фото подписи на белом**. На восстановленном кропе паспорта haze-cutoff и `MaxFilter(3)` доедают бледное и схлопывают bbox до ~160 px.

## 6. Что пробовали и почему сломалось

| Идея | Почему не сработало |
|---|---|
| Оцу / max(RGB) как «чернила» | Синяя шариковая яркая в B → пропадает. Штамп «32» перебивает порог. |
| `min(R,G)` для синего пера | На синтетике ок, на смазе Пытель штрих дырявый. |
| Claude: «обведи полилиниями» | Рисует **свою** геометрию. Промпт «много точек, следуй фото» не лечит. |
| Жирный `binary_closing` | Толстые острова, линейка сливается с росчерком. |
| Claude «осевая» + клип по маске | Клип по дырявой маске выбивает пиксели → пунктир. Модель всё равно отдаёт 3 грубых штриха. |
| Вычесть линейку opening / подгонкой прямой | Линейку убрать можно. Подпись от этого не появляется. |
| Мягкая хрома (бумага − RGB, синева + темнота) → альфа | Человек видит непрерывность в полутонах; после стретча/гистерезиса остаются пятна. |
| Банк ориентированных гауссиан + NMS / скелет | Усиливает пики, рвёт бледные связки. Скелет 10–40 коротких путей. |
| Склеить концы путей, если близко | На Пытель разрывы больше, чем разумный gap, либо склеивается мусор. |
| Крупный morphological closing | Либо не смыкает (пятна далеко), либо прихватывает линейку/фон. |
| Тighter crop: отрезать «32» и низ с линейкой | Кроп чище, обводка всё равно осколки. |
| «Обвести тонкой гладкой линией и стилизовать пером» | Это v6: осевые по скелету + антиалиасинг-перо. На смазе скелет не является её подписью. |
| Тесты на синтетике | Зелёный pytest ≠ годный прод. Синтетика не ловит кейс Пытель. |

**Диагноз, который повторять бесполезно:**

1. Порог по яркости на смазе физически не восстанавливает линию.
2. Векторизация через LLM — не трассировка, а упрощение до чужого автографа.
3. Клип «только там, где есть чернила» уничтожает как раз дорисованные связки.
4. Скелет по дырявой маске даёт осколки; скелет по жирной маске даёт кляксы.
5. Нормализатор заточен под белый фон, не под кроп паспорта.
6. Тончайшие участки ручки на фото Пытель по яркости как зерно бумаги. Человек «дорисовывает» глазом; алгоритм без права выдумывать штрих честно рвёт линию.

## 7. Ограничения (если когда-нибудь вернёте фичу)

- Не рисовать выдуманную подпись и не «улучшать» до каллиграфии.
- Не коммитить фото паспорта / кропы клиентов (`docs/handoff_assets/` в `.gitignore`).
- Сервер: Python 3.10. Стек продукта снова **без** numpy/scipy (сняты вместе с фичей). Если снова понадобятся — `requirements.in` + `pip-compile`, совместимость с 3.10 (`numpy<2.3`, `scipy<1.16`).
- Общение с пользователем — **на русском**. Коммиты: `fix:` / `feat:` / `refactor:` / `docs:`.
- «Заканчиваем работу» = changelog + commit + push `master` + `.\scripts\deploy.ps1`.
- PowerShell, не bash (`&&` нет, heredoc нет).

## 8. Направления, которые ещё не доказали себя

Это **не ТЗ**. Владелец продукта откатил фичу. Новый заход имеет смысл только с другим принципом.

**A. Не векторизовать.** Усилить кроп как фото: хрома, вычесть линейку, отдать растр. Пробовали (v4) — форма ближе всех к эталону, но «не тонкие сплошные линии».

**B. Реконструкция штриха без LLM.** Hysteresis / ridge / tensor voting. Пробовали ориентированные фильтры и скелет (v5–v6) — осколки.

**C. Vision → картинка, не JSON.** API Claude не отдаёт PNG. SVG-path — всё ещё вектор (риск v1). Отдельная модель сегментации чернил — не пробовали.

**D. Два режима.** Чёткий скан → очистка. Плохое фото → честный `None`. Это и есть текущая продуктовая позиция: плохое фото = загрузите подпись сами.

**E. Нормализатор не трогать полутона** на выходе из паспорта. Имеет смысл только если появится годный растр.

**F. Эталон в тесте.** Не класть паспорт в git: синтетический смаз + линейка + штамп, плюс ручная проверка на кропе Пытель локально. Синтетика **не заменяет** глазами Пытель.

Имеет смысл **не** возвращать `_trace_centerlines_with_ai` / `_rasterize_trace` как основной путь.

## 10. Как проверять после любых правок размера (не считывания)

1. Загрузить своё фото подписи в слот — превью синее на прозрачном.
2. Обязательство PDF: подпись не миллиметровая нитка и не прыгает от файла к файлу.
3. `pytest core/tests/test_transport_docs.py::test_signature_flowable_respects_max_box` и `::test_signature_flowable_wide_image_not_tiny`.
4. «Сгенерировать всё» без файла подписи — ошибка, пакет не создаётся.

Если снова включат авто-извлечение: удалить слот «Подпись» у заявки Пытель и сравнить PNG с `pytel_passport_crop.jpg` глазами. Зелёный pytest недостаточен.

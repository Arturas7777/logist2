# Changelog

Все значимые изменения в Logist2 будут документироваться в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект следует своей внутренней схеме версий (см. git-теги).

## [Unreleased]

### Changed — Короткие названия таможенных процедур (2026-08-20)

- Процедуры называются «Транзит (T1)», «Экспорт», «Импорт», «Реэкспорт»
  вместо «Транзитная (T1)» / «Экспортная» / «Импортная». Меняется везде
  сразу: доска и карточка заявки, кабинет клиента, стандартная админка,
  матрица требований к документам. Литовское письмо складу не затронуто.

### Changed — Машины на доске заявок сгруппированы по декларациям (2026-08-20)

- Карточка на `/admin/requests/` показывает не плоский список машин, а блок
  на каждую декларацию: номер, тип (транзит / экспорт / импорт / реэкспорт),
  число авто и примечание. Отдельные декларации, собранные сотрудником,
  выделены фиолетовой полосой и меткой «отдельная»; декларации на несколько
  авто — залитым чипом «N авто вместе». Если тип не выбран, вместо прочерка
  у машины выводится предупреждение.
- Длинный перечень недостающих документов на карточке переносится по словам
  и больше не уезжает за её край.

### Fixed — Поиск на доске заявок не отрывается вправо (2026-08-20)

- Форма поиска больше не прижимается к правому краю широкой страницы, когда
  табы состояний занимают всю строку: она встаёт под ними по левому краю,
  в одну линию с карточками.

### Added — Тайтл обязателен в пакете и прикрепляется сам (2026-08-20)

- «Тайтл» — новый тип документа пакета, обязательный при любой стране и
  процедуре: даже если в матрице требований галочку не поставили, код
  добавляет его к набору (`transport_request_check._ALWAYS_REQUIRED`).
- Если скан лежит в карточке авто (`Car.title_scan`), он копируется в
  документы заявки автоматически — при открытии кабинета клиентом или
  карточки заявки сотрудником, при добавлении авто в заявку и сразу при
  применении скана к машине. Клиент грузит тайтл сам только когда у нас
  его нет. Наш тайтл клиент не удаляет (вернётся при следующем открытии);
  удаление сотрудником = обновление копии из карточки авто.
- В сборном PDF пакета тайтл больше не дублируется, а AI-разбор «Одним
  файлом» раскладывает страницы Certificate of Title в свой слот.

### Added — Страна назначения, матрица требований и разбор пакета AI (2026-08-20)

- Клиент в заявке выбирает страну назначения и таможенную процедуру
  (транзит / экспорт / импорт / реэкспорт); процедура подставляется по
  стране (Беларусь и Молдова — транзит, Украина — реэкспорт) и меняется
  вручную. Страна попадает в письмо складу.
- Обязательные документы задаются в админке на пару «страна + процедура»
  (`TransportDocumentRule`), с встроенным фолбэком, если строки нет.
  Кабинет показывает клиенту, каких документов не хватает.
- Кнопка «Одним файлом»: клиент грузит весь пакет одним PDF, Claude Vision
  определяет тип каждой страницы, файл режется по документам и
  раскладывается по слотам (`transport_bulk_split` + задача Celery с
  повтором при лимитах Anthropic). Нераспознанное падает в «Остальное»,
  клиент указывает тип сам.

### Added — Администрирование заявок на автовоз (2026-08-20)

- Доска заявок и карточка заявки в админке: данные автовоза, машины с
  полнотой пакета документов, блокеры отправки складу.
- Письмо-заявка складу на литовском: адресаты из общей почты склада и
  контактов, ответы склада матчатся к заявке по треду и номеру и видны
  в карточке — оттуда же можно ответить.
- Переписка с клиентом по заявке: замечания и запрос документов
  (клиент видит кнопки загрузки нужных типов), счётчики непрочитанного
  с двух сторон, уведомления на email и в Telegram.
- Декларации заявки настраиваются гибко: по умолчанию одна на все авто,
  при необходимости — отдельные декларации своим типом на подмножества
  машин (`TransportDeclarationGroup`). Клиенту эта разбивка не видна.
- Из заявки создаётся рейс автовоза (перевозчик сопоставляется по EORI).

### Fixed — Площадка склада не сбрасывается на первую при сохранении авто (2026-08-19)

- В карточке авто Select2 при открытии формы слал ложный `change` склада.
  `warehouse_address.js` воспринимал его как смену склада и подставлял
  площадку 1. У ATLANTIC это Nevezio 5 вместо выбранной Minijos 181.
  Ложное событие больше не сбрасывает адрес; сброс только при реальной
  смене склада.

### Fixed — Сохранение наценки в каталоге услуг склада (2026-08-13)

### Added — Автообновление ETA контейнеров из Track & Trace API морских линий (2026-08-10)

- **`core/services/eta_tracker.py`**: запрос событий контейнера по стандарту
  DCSA у Maersk (`api.maersk.com`, заголовок `Consumer-Key`) и CMA CGM
  (`apis.cma-cgm.net`, заголовок `KeyId`); ETA = самое позднее плановое
  прибытие (PLN/EST ARRI) — при трансшипментах это конечный порт.
- **Триггеры**: после применения dock receipt (номер + линия известны) —
  немедленный запрос ETA; ежедневно в 05:45 — обновление всех контейнеров
  «В пути» (`update_container_etas_task` в celery beat).
- **Настройка**: env-ключи `MAERSK_CONSUMER_KEY` и `CMA_CGM_API_KEY`
  (`logist2/settings/base.py`); линии без ключа/адаптера пропускаются.
  MSC подключим после получения доступа к их порталу.
- Тесты: `core/tests/test_eta_tracker.py` (моки, без сети).

### Added — Загрузка dock receipt и тайтлов в карточку контейнера с надёжным распознаванием VIN (2026-08-09)

- **Панель «Документы (AI)» в карточке контейнера**
  (`templates/admin/core/container/_documents_panel.html`): drag-and-drop
  загрузка dock receipt и тайтлов (PDF/JPG/PNG) прямо из карточки, статусы
  обработки в реальном времени и кнопки действий (Применить / Создать новый
  Car / Повторить / Игнорировать) — весь workflow без ухода на страницу
  задач. AJAX-эндпоинты в `core/admin/container.py`.
- **Надёжное чтение VIN** (`core/services/vin_corrector.py`, переработан
  `scan_extractor.py`): рендер страниц с высоким DPI + тайлинг, второй
  посимвольный проход по VIN, нормализация запрещённых I/O/Q, автокоррекция
  по контрольной цифре (таблица OCR-путаниц), скоринг уверенности
  high/medium/low (checksum + NHTSA + повторное чтение).
- **Контекст контейнера**: `ScanProcessingJob.target_container` (миграция
  `0014`) — VIN тайтла матчится в первую очередь по машинам этого
  контейнера (fuzzy ≤ 2 символа), dock receipt применяется к нему без
  поиска по номеру.
- **Авто-применение** (`scan_applier.evaluate_auto_apply/maybe_auto_apply`):
  уверенные результаты применяются без ручного review — тайтл при
  однозначном матче VIN, dock receipt при совпадении номера и high-VIN;
  машины создаются из dock receipt с весами (кг) и наследуют
  склад/клиента/линию контейнера. Заполненные вручную поля (например BOL
  в booking number) не перетираются. Причина решения — в
  `extracted_data.auto_apply_skipped` / `applied_changes.auto_apply_reason`.
- Тесты: `core/tests/test_scan_vin_pipeline.py`.

### Fixed — Галочка «Т» (тайтл у нас) сбрасывалась при сохранении карточки контейнера (2026-08-09)

- **Причина**: AI-обработка ставила `Car.has_title=True`, пока карточка
  контейнера была открыта; при последующем «Сохранить» инлайн машин
  перезаписывал галочку устаревшим значением из формы (Django сравнивает
  POST со свежим initial из БД и считает строку изменённой).
- **Исправление**: панель документов при каждом обновлении статусов
  синхронизирует чекбоксы «Т» в инлайне с БД (+ retry поллинга при сетевых
  ошибках), эндпоинт `scan-jobs` отдаёт `car_vin`/`car_has_title`.
- **`title_notes` больше не заполняется автоматически** — поле только для
  ручных заметок оператора; сводка тайтла (номер/штат/дата) осталась в
  `applied_changes.title_info` задачи.

### Fixed — Совместимость с claude-sonnet-5 во всех AI-сервисах (2026-08-09)

- **Модель**: `claude-sonnet-4-20250514` удалена из Anthropic API (404) —
  дефолт `AGENT_MODEL` обновлён на `claude-sonnet-5`, добавлена настройка
  `SCAN_AI_MODEL` (`logist2/settings/base.py`).
- **`temperature` deprecated** у новых моделей — параметр убран из всех
  вызовов `messages.create`.
- **Thinking-блоки**: claude-sonnet-5 может возвращать блоки размышлений
  перед текстом, `response.content[0].text` падал с `AttributeError:
  'ThinkingBlock' object has no attribute 'text'`. Добавлен общий хелпер
  `core/services/llm_text.py` (собирает только text-блоки), подключён в
  scan_extractor, invoice_audit, receipt_parser, expense_analytics;
  `max_tokens` для сканов поднят до 4000 (thinking расходует тот же бюджет).

### Added — Удаление заявки на автовоз клиентом + ужесточение правил редактирования (2026-08-09)

- **Кнопка-корзина** на странице «Мои заявки» рядом с редактированием
  (`templates/website/client_transport_requests.html`), с подтверждением.
- **Мягкое удаление**: заявка получает новый статус «Отменена»
  (`TransportRequest.STATUS_CHOICES` + миграция `0013`), скрывается из
  кабинета клиента, но остаётся в админке с красным бейджем — администратор
  видит, что заявка неактуальна. Авто из отменённой заявки снова доступны
  для новых заявок (метка «Уже в заявке» снимается).
- **Правила**: редактирование и удаление возможны только в статусах
  «Черновик»/«Подана» (`CLIENT_EDITABLE_STATUSES`); правка «Принятой»
  со сбросом в «Подана» убрана — у «Принятой» кнопок больше нет.
  Вьюха `transport_request_delete` (`core/views_website/portal_transport.py`).

### Fixed — 403 «Ошибка проверки CSRF» при отправке форм кабинета на проде (2026-08-09)

- **Причина**: `SESSION_COOKIE_SAMESITE`/`CSRF_COOKIE_SAMESITE = "Strict"`
  (`logist2/settings/prod.py`). При заходе на сайт по внешней ссылке или
  повторном логине в другой вкладке браузер не отправлял Strict-куки,
  Django выпускал новый csrftoken, и формы в уже открытых вкладках падали
  с «CSRF token from POST incorrect» (например, создание заявки на автовоз).
- **Исправление**: обе куки переведены на `Lax` (дефолт Django; от
  кросс-сайтового POST по-прежнему защищает сам токен + Lax не шлёт куки
  на чужие POST). Плюс дружелюбная страница ошибки CSRF
  (`core/views_website/errors.py`, `templates/website/csrf_failure.html`)
  вместо голого 403 — объясняет, что форма устарела, и предлагает
  вернуться и повторить.

### Fixed — Карточка авто в кабинете клиента: цвета статусов + шапка с картинкой модели (2026-08-09)

- **Цвета статусов** (`templates/website/car_detail.html`): статус
  «Разгружен» отображался почти чёрным (`bg-primary` темы), «Передан» —
  зелёным. Теперь единая гамма проекта, как на дашборде: В пути — голубой,
  В порту — красноватый, Разгружен — зелёный, Передан — фиолетовый.

### Changed — Мотоциклы вне счёта авто + FLEXIBLE = ровно тариф (2026-06-17)

### Fixed — FIXED-тариф: цена пакета не выше тарифа, превышение = убыток (2026-06-17)

- Для клиентов с тарифом `FIXED` складской пакет (услуги склада без хранения)
  теперь всегда приводится **ровно** к сумме тарифа — цена не может быть выше

## Соглашения

- **fix:** исправление бага.
- **feat:** новая функциональность.
- **refactor:** рефакторинг без изменения поведения.
- **docs:** документация.
- **chore:** инфраструктура, конфиги, зависимости.
- **perf:** оптимизация производительности без изменения поведения.
- **style:** UI/CSS, без логики.
